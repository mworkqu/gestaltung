# CLAUDE.md

PROJECT: Gestaltung — a manufacturing marketplace and inventory platform for Qatar.

## WHAT THE BUSINESS DOES
- Clients upload 3D/CAD files (STL, STEP, DXF, IGES).
- The platform identifies the right manufacturing method (3D printing, CNC machining, laser cutting, EDM).
- Jobs are dispatched to partner workshops across Qatar, who produce the part.
- The finished product is delivered back to the client.
- A second module is e-commerce for high-quality mechanical parts (screws, nuts, fasteners).
- The backbone is a multi-tenant inventory system.
- 2026-10 note: the studio makes parts itself in Lusail (Prusa MK4, CNC, laser); there are no partner workshops and no automatic method detection — copy must never promise either.

## USERS / ROLES
- Super Admin (the owner): sees ALL data across every workshop and client in Qatar.
- Workshop: a partner producer with their own isolated inventory and jobs.
- Client: a customer with their own isolated orders and inventory.

Each tenant only ever sees their own data. The Super Admin sees everything.

## Hard rules
- Public storefront pages stay static/ISR: no `cookies()`, `headers()`, `searchParams` or `force-dynamic` there, and they call `setRequestLocale`. Public reads go through `lib/store/public-catalog.ts` (cookie-free client + `unstable_cache`). Cache expiry is 24 h (see Permanent notes).
- Every write to a store table (parts, supplier_offers, suppliers, store_settings) calls `revalidateStorefront()` from `lib/cache/storefront.ts`.
- EN and AR messages stay in parity: run `node scripts/check-i18n-parity.mjs` after any message change.
- A new client component's message namespace goes into `lib/i18n/scopes.ts`; the root layout sends only `BASE_MESSAGES`.
- Expression-bodied `useEffect` / `useLayoutEffect` is banned by lint (a returned Promise is called as cleanup and crashes the page). Use a block body.
- `content/legal/**` is generated by `scripts/split-legal-draft.mjs` from `LEGAL_PAGES_DRAFT.md`. Never hand-edit it, and never change legal wording (owner decision D8). Check with `node scripts/split-legal-draft.mjs --check`.
- No paid services or subscriptions, and never sign the owner up for any (owner rule, 2026-06-10).
- Never promise a reprint or rework in copy or code. No invented numbers (no confidence bars, lead days, critical path). The model outputs structure, never pixels, and proposes a function, never a product (no SKU, price, brand, stock or lead time from a model).
- Copy never mentions partner workshops or automatic method detection (the studio makes parts itself in Lusail; an engineer quotes the method).
- Migrations: never edit an applied migration. New ones are numbered from 0106, idempotent, carry a rollback note in the header, have a PGlite test (pattern: `lib/schools/db/schools-migration.test.ts`) and are listed in `docs/MIGRATIONS.md`.
- The e2e suite is read-only against production Supabase and runs behind the write guard in `e2e/fixtures.ts`. Never weaken the guard.
- Design: all pages use the light "neu precision" design system (`DESIGN.md`, how-it-works is the reference). The landing and public header carry no inventory link; inventory is reachable only from the dashboard and account menu.
- Never print or copy secret values, never create env files in a shared checkout, never run `vercel` or push without the owner asking.

## Architecture map
- Stack: Next.js 15 App Router (webpack build), React 19, TypeScript strict, Tailwind 3, next-intl 4 (`en` default, `ar` RTL), Supabase, zod 4, vitest, Playwright. Detail: `docs/audit/CODE_MAP.md`.
- Folders: `app/[locale]/**` pages and server actions; `app/api/**` route handlers; `lib/<area>/**` logic; `components/**` UI (`components/studio/**` PascalCase); `messages/{en,ar}.json`; `i18n/`; `supabase/migrations/`; `services/cad-worker/` (optional cloud CAD worker).
- Layer rules (what may import what):

| Layer | Where | May import | Must not import |
|---|---|---|---|
| Pure domain logic | `lib/<area>/*.ts` | other `lib/`, zod | React, `next/*`, Supabase clients |
| Server data access | `lib/<area>/server*.ts`, `lib/<area>/db/` | `lib/supabase/{server,service,public}`, `next/cache` | React components |
| Client helpers | `lib/<area>/client/*.ts`, `use-*.ts` | `lib/supabase/{client,lazy}` | `next/headers`, service client |
| Route handlers | `app/api/**/route.ts` | one `lib/<area>/server`, `lib/http.ts`, `lib/auth/guards.ts` | business rules inline (parse, guard, call lib, respond) |
| Server actions | `app/[locale]/**/actions.ts` | `lib/auth/guards.ts`, `lib/<area>/server` | hand-rolled role checks |
| Pages / layouts | `app/[locale]/**` | guards, lib server modules, components | long `.from()` chains, money/date maths |
| UI | `components/**` | `lib/<area>/client`, pure `lib/` | `lib/supabase/service`, SQL-shaped logic |

- Supabase clients: `lib/supabase/client.ts` (browser, anon), `server.ts` (cookie-bound, anon + RLS), `service.ts` `createServiceClient()` (service role, bypasses RLS, returns null without the key; server only), `middleware.ts` `updateSession()`. Types are hand-written in `lib/supabase/types.ts`.
- Auth: `lib/auth/get-session.ts`, `guards.ts`, `guest-redirect.ts`, `next-path.ts` (redirect sanitising), `claim-guest*.ts`. Roles `super_admin | workshop | client` in `profiles.role`; guests are Supabase anonymous users (`is_anonymous`), created lazily by `ensureSession()` in `lib/supabase/guest.ts`. `tenants`/`inventory_items` is a legacy model.
- Middleware: `middleware.ts` does next-intl routing, the `site_v2` flag and a session refresh only when an auth cookie is present.
- Money path: cart (`cart_items`, guests included) -> `/store/checkout` -> RPC `create_part_order` (latest 0097) -> order emails (`lib/email/**`, `notification_outbox`) -> `/orders`. Currency QAR; payment is manual (cash on delivery, Fawran, bank transfer); no card gateway.
- Credits: `credits_ledger`, `spend_credit` / `credit_can_use` (0042, 0052, 0053, 0096), edu grants (0074/0075), tokens (0088), payments / maker pass (0089), CAD cost rewards (0090).
- AI paths: `/api/analyse`, `brief-chat`, `cad`, `project-cad`, `firmware`, `netlist`, `bom/**`, `studio/**` (Gemini / Groq via `lib/ai`, `lib/prototyping/providers`, `lib/studio/**`); cloud CAD worker via Google WIF (`docs/CAD_CLOUD.md`). Every AI call is metered by credits.
- Crons (`vercel.json`, UTC, `Authorization: Bearer $CRON_SECRET`): delivery-promises, voltaat-sync, supplier-refresh, notifications, anonymous-cleanup, youtube-retire.
- Email: everything goes through `lib/email/brand-layout.ts` `renderBrandedEmail()`.
